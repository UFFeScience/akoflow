Infrastructure selection for training

Compare plans for local GPU, HPC, and cloud before executing the selected candidate.

PUBLISHED ON AKÔFLOW HUB

Explore this workflow and its measured results

The interactive DAG, version and execution summary below come directly from the public Hub publication.

Run this example locally

Measure a local CPU model fit, compare three infrastructure plans using explicitly declared speed/startup/price assumptions, select a plan, and train the final model locally. This smoke example provisions no infrastructure and reports estimates separately from measured error.

Install Go and Python 3.12 or newer.

git clone https://github.com/UFFeScience/akoflow-examples.git &&
cd akoflow-examples &&
git checkout --detach showcase-hub-v1 &&
cd machine-learning/infrastructure-selection &&
./prepare.sh &&
./run.sh

Run the block from the directory where you keep your repositories. If you already cloned the repository, enter this example's directory and run ./prepare.sh && ./run.sh.

Preparation downloads the Go module and any declared Python packages once. The workload then runs locally with offline input data. Every meaningful step is a separate process; independent activities run in parallel after their dependencies complete.

Read outputs/manifest.json for the generated artifacts, outputs/dag-validation.json for dependency waves, and outputs/stage-<activity>.json for each activity's observed result. A failed stage stops the run and prevents a successful final manifest.

Expected outputs: decision.json, cost-comparison.csv.

Run the same activities in Desktop

Start your local AkôFlow daemon with Docker available and configure AKOFLOW_API_TOKEN in your shell. From this example's directory, run:

go run ../../tools/daemon-local -root ../.. -example machine-learning/infrastructure-selection

This command validates the daemon connection, builds the declared image, registers the local environment and workflow, and submits a real run. The daemon owns execution and file transfers. Open the printed run ID in Desktop to inspect each activity.

Execution considerations

Evaluate candidates with frozen inputs and one common model. Queue planning experiments so concurrent load does not distort evidence.

AkôFlow boundary: the engine schedules, deploys, executes, transfers data, and records evidence. The ML or agent framework remains an implementation choice inside each activity.

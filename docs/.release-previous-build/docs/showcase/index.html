Showcases

Explore 31 core executable workflows organized by technical domain, plus one data-transfer workflow with multiple execution profiles. Each page explains the workflow DAG, activity responsibilities, inputs, outputs, provenance, and execution considerations without embedding implementation code in the documentation.

The complete Dockerfiles, Python programs, generators, input fixtures, runners, and validators are maintained separately in UFFeScience/akoflow-examples. A single source-bundle link on each page connects the explanation to its versioned implementation.

Public workflows and results​

Open the official AkôFlow workspace in Hub. Published showcase pages include an immutable import URI, the workflow YAML, an illustrated README, and measured execution results. Import the URI through Create workflow → Import from Hub in Desktop, then configure the runtime prerequisites described on the showcase page before execution.

Additional infrastructure profiles​

The original infrastructure definitions remain available as historical Hub versions. Their portable local profiles execute the same computation and file-content checks on a local Docker host. These measurements do not verify GCP provisioning or Kubernetes placement.

  • Data-transfer workflows and their execution profiles.
  • Montage 050 execution profiles: validated local run and optional GCP configuration.
  • Download the publication and immutable import-URI manifest.

Validation model​

Each page includes a copyable local command, its prerequisites, a precise description of the portable workload, and its expected output files. The 27 small examples execute real CPU computations and have both standalone local validation and completed Docker-backed daemon runs. The reference documentation includes 171 activity captures and 27 observed DAGs. Fresh completed Docker-backed execution captures, validated outputs and immutable import URIs are available in Hub for the full catalog.

The local profiles are deliberately small and explicit: for example, geometric images instead of CIFAR-10, a rank-one adapter on a tiny matrix instead of an LLM, TF-IDF retrieval instead of hosted embeddings, and a synthetic tone vocabulary instead of natural-speech recognition. GPU, edge, and infrastructure comparison profiles distinguish CPU measurements from declared placement assumptions. The training example uses the actual MLflow SDK and a local SQLite tracking store.

Montage 050 is the full 58-activity scientific workflow. Its new homeserver execution completed all 58 activities; the three 1800×1800 FITS mosaics and four PNG previews passed their output validator. The GCP deployment profile belongs to this same publication and is marked as an unexecuted reference configuration. The public catalog contains 29 distinct publications.

Read the historical standalone verification records. Provider-specific execution on HPC, Kubernetes, or cloud infrastructure still requires the environment described by the corresponding infrastructure guide.

# Workflow showcase

Each example includes versioned files, an API submission path, and an expected result. Some simulate work; others run real workloads. The SLURM fixture checks only the local adapter path. Use Desktop to inspect records when it is connected to the same server used for submission.

The showcase is organized in two collections:

- **Infrastructure and execution** contains complete, runnable examples for SimGrid, Kubernetes, local execution, and SLURM.
- **[AI workflow patterns](/docs/showcase/ai/)** contains independent DAG designs for machine learning, generative AI, agent loops, and AI-assisted science. These patterns focus on workflow structure; runnable bundles can be added without introducing AI-specific behavior into the AkôFlow engine.

## How to use a showcase

1. Choose a scenario and open its v1.0.8 checkout.
2. Complete the scenario's prerequisites and [API connection setup](/docs/tutorials/api-access) when using an existing server. The SLURM fixture starts its own server and sets its API URL in the procedure.
3. Submit the files in the stated order and wait for the run to finish.
4. Check the result listed on that scenario's page.

The files define the submitted model. If Desktop is connected to the same server, use it to inspect the saved records and result.

## Infrastructure configuration references

These files model infrastructure inputs, but are not end-to-end showcases. In particular, they do not include a portable cluster, a submitted run, or observed execution evidence.

| Infrastructure | Files | Scope and next step |
| --- | --- | --- |
| SLURM cluster | [`examples/slurm`](https://github.com/UFFeScience/akoflow/tree/v1.0.8/examples/slurm) | A catalog for a partition, login node, shared storage, and runtime bindings. Pair it with an approved SLURM cluster and follow [Connect an HPC and SLURM cluster](/docs/guides/infrastructure/hpc-slurm) before submitting a site-approved probe. The separate [SLURM batch fixture](/docs/showcase/slurm-local-fixture) validates only the local adapter path. |

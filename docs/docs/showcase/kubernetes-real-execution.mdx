# Kubernetes real execution

<WorkflowDiagram kind="kubernetes" />

This example executes two real container activities on a local Kind cluster. Use it after the simulation walkthrough to validate runtime credentials, persistent storage, Kubernetes Jobs, logs, artifacts, and provenance.

:::warning Development environment
The checked-in access manifest intentionally grants broad permissions for a disposable local cluster. Do not reuse it in production.
:::

    <h2>Run with AkôFlow Desktop</h2>
    <ol>
      <li>Create the Kind cluster and apply <code>akoflow-access.yaml</code> and <code>storage.yaml</code>.</li>
      <li>Generate a ServiceAccount token. In <strong>Infrastructure → Environments</strong>, create a Kubernetes environment and store that token in the daemon credential flow.</li>
      <li>Test the connection and run discovery. Confirm that the Kind worker appears as a schedulable resource.</li>
      <li>Create a scope and topology matching the supplied YAML, then import <code>dag.yaml</code> under <strong>Workflows → Definitions</strong>.</li>
      <li>Create a manual plan or generate candidates, select the Kind resource, and start a <strong>Real execution</strong>.</li>
      <li>Inspect activity logs, generated files, artifacts, timeline, events, and provenance after completion.</li>

    <h2>Run through the API</h2>

  "execution-scopes examples/kind/scope.yaml" \\
  "network-topologies examples/kind/topology.yaml" \\

done`}</code></pre>

## Expected evidence

A successful run produces Kubernetes Jobs and Pods for both activities, persisted activity logs, run lifecycle events, and artifacts from the shared workspace. The AkôFlow run detail remains the canonical projection even after Kubernetes history cleanup.
